Source, scope & interpretation

A useful statistic includes its limits. Here is how this instance turns Steam responses into player activity.

01—06
01

Players means concurrent activity.

The Steam current-player endpoint supplies the number of users currently active in an app. Game Census records the validated count and the time its collector received the response. Steam does not supply an observation timestamp for this method.

These are Steam-reported concurrent players, not unique daily players, owners, sales, or verified humans. A valid zero is a real observation. A failed request never becomes zero.

02

Freshness is visible.

A count is fresh at the time of the page read when its age is no more than {{ freshness_multiplier }} times the app's configured interval. Older counts are labeled stale and shown as last observed. Fresh receipt does not prove that Steam's own underlying value was just updated.

Collection outcomes remain separate from the last valid count. An app without a successful observation shows an unavailable value, not an invented estimate. Refreshing this site only reads local storage.

03

History begins here.

Game Census retains its own observations. There is no SteamDB import or fabricated history before tracking began. The observed 24-hour peak is the highest received count in that period. Highest recorded is the largest count recorded by this instance since tracking began.

Neither is a game's all-time Steam record. Missing samples may hide a higher peak. Every chart reports its observation count and time coverage.

04

Gaps stay gaps.

The average observed CCU is a time-weighted average. Each observation contributes its value until the next observation, the window end, or {{ gap_multiplier }} times its configured interval—whichever arrives first. Uncovered time adds no value and no weight. An average with no covered time is unavailable.

Coverage is covered seconds divided by requested seconds. It includes missing time before tracking began. Expected samples use the configured cadence within enrolled time; manual runs do not imply that a scheduler is active. The maximum gap identifies the longest uncovered span in the requested window.

Charts connect nearby observations and break across cadence-capped gaps. Use the observation table for exact samples. Times and half-open window boundaries are UTC. Requests allow up to {{ max_history_days }} days and {{ max_points|number }} points; oversized requests fail with an actionable limit rather than silently dropping points.

05

An enrolled cohort, not all of Steam.

The activity list contains all apps enrolled on this instance. Fresh observations appear first, followed by last known counts. Previously enrolled apps and their history remain visible when collection configuration changes. The current configuration determines the next manual collection's targets; initialization enrolls those targets. An unenrolled ID is outside this instance's coverage, even if it exists on Steam.

This first version collects current players and derives recorded player history. Optional Steam Store metadata supplies game names. Catalog discovery, price history, review statistics, achievements, and news are not enabled. App names are displayed only when available; an app ID is a usable identity on its own.

06

Independent and read-only.

This interface reads stored observations through the versioned read API. The OpenAPI contract describes its routes and bounds. Browser requests never collect from Steam. Operators use shipped commands for setup and bounded manual collection.
